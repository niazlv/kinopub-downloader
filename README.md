# kinopub

CLI-утилита для скачивания видео с kino.watch (бывший kino.pub) в полном качестве — все аудиодорожки (с названиями студий озвучки), все субтитры, мультисезонные сериалы.

Домен нигде не захардкожен: сайт берётся из переданной ссылки, поэтому любое зеркало или новый домен работают без правок кода. См. [Домены и зеркала](#домены-и-зеркала).

## Возможности

- Скачивание по ссылке на страницу (`/item/view/...`) или по прямой ссылке на podcast feed
- Любой домен: kino.watch, kino.pub, произвольные зеркала — ссылка задаёт сайт
- Все аудиодорожки с метаданными (студия озвучки)
- Выбор и фильтрация аудиодорожек (`--audio anilibria`, `--audio "!jpn"`, `--audio-menu`)
- Выбор и фильтрация субтитров (`--subs rus`, `--subs "!eng"`, `--subs-menu`), отдельные `.srt` (`--subs-external`) и режим `--subs-only`
- Выбор сезонов и эпизодов (`--seasons 1,3-5 --episodes 1-12`); суффикс `/s1e1` в ссылке тоже работает как фильтр
- Выбор качества: автоматически, флагом (`-q 1080p`) или интерактивным меню (`--video-menu`)
- Интерактивный режим `-i`: качество → аудио → субтитры, затем скачивание
- Прогресс-бар в терминале
- Возобновление прерванных загрузок (state-файл)
- Умные повторы при сбоях CDN: проблемный эпизод откладывается и до-качивается позже, чередуясь с остальными (а не пропускается)
- Проверка и восстановление загрузок (`kinopub doctor`)
- Поддержка прокси (HTTP, HTTPS, SOCKS5)
- Контейнеры MKV (по умолчанию) и MP4
- Зашифрованное хранение авторизации (`kinopub login`)
- Самообновление (`kinopub update`) с проверкой контрольных сумм; только для официальных сборок

## Установка

### Из релизов (рекомендуется)

Скачайте бинарник для вашей платформы со [страницы релизов](https://github.com/niazlv/kinopub-downloader/releases/latest):

| Платформа | Архитектура | Файл |
|-----------|-------------|------|
| macOS | Apple Silicon (M1/M2/M3) | `kinopub-darwin-arm64` |
| macOS | Intel | `kinopub-darwin-amd64` |
| Linux | x86_64 | `kinopub-linux-amd64` |
| Linux | ARM64 (Raspberry Pi и др.) | `kinopub-linux-arm64` |
| Android / Termux | ARM64 | `kinopub-android-arm64` |

```bash
# Пример для macOS Apple Silicon:
chmod +x kinopub-darwin-arm64
mv kinopub-darwin-arm64 /usr/local/bin/kinopub

# Пример для Linux:
chmod +x kinopub-linux-amd64
sudo mv kinopub-linux-amd64 /usr/local/bin/kinopub
```

### Из исходников

```bash
go install github.com/niazlv/kinopub-downloader/cmd/kinopub@latest
```

Или:

```bash
git clone https://github.com/niazlv/kinopub-downloader.git
cd kinopub_downloader
go build -o kinopub ./cmd/kinopub
```

## Быстрый старт

### 1. Авторизация

Сайт защищён Cloudflare. Для скачивания нужны куки из залогиненного браузера.

**Способ 1: Копирование куки из DevTools (работает везде)**

1. Откройте сайт (kino.watch) в браузере, залогиньтесь
2. Откройте DevTools (F12) → Network
3. Обновите страницу, кликните на первый запрос
4. Скопируйте значение заголовка `Cookie` из Request Headers
5. Скопируйте значение `User-Agent`

```bash
kinopub login \
  --cookie "cf_clearance=...; _identity=...; PHPSESSID=..." \
  --user-agent "Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7) ..."
```

**Способ 2: Автоматическая загрузка из браузера (только macOS)**

Требует Full Disk Access для терминала (System Settings → Privacy & Security → Full Disk Access).

```bash
kinopub login --browser-cookies safari
```

Куки ищутся по очереди для всех известных доменов (kino.watch, затем kino.pub) — не нужно помнить, под каким из них вы залогинены. Для зеркала укажите домен явно:

```bash
kinopub login --browser-cookies safari --site kino.example
```

> Credentials сохраняются зашифрованными в `~/.config/kinopub/credentials.enc` и привязаны к конкретному устройству (расшифровать на другой машине невозможно).

### 2. Скачивание

```bash
# По ссылке на страницу (самый простой способ)
kinopub -o ./downloads https://kino.watch/item/view/38290

# По прямой ссылке на podcast feed (не требует авторизации)
kinopub -o ./downloads https://kino.watch/podcast/get/38290/TOKEN

# Только 1 сезон, 1080p
kinopub -o ./downloads --seasons 1 -q 1080p https://kino.watch/item/view/38290

# Посмотреть что будет скачано (без загрузки)
kinopub --dry-run https://kino.watch/item/view/38290
```

### Домены и зеркала

Утилита не привязана к конкретному домену. Сайт определяется хостом переданной ссылки, и от него зависят всё остальное: адрес podcast feed, заголовок `Referer` и то, куда отправляются куки сессии.

```bash
# Новый домен
kinopub https://kino.watch/item/view/38290

# Старая ссылка на kino.pub тоже работает — домен автоматически
# заменяется на актуальный (см. ниже)
kinopub https://kino.pub/item/view/38290

# Любое зеркало — просто передайте его ссылку
kinopub https://kino.example/item/view/38290
```

Ссылки со старым доменом сайта (kino.pub) — переданная в аргументе, а также page/media/poster-ссылки внутри feed — автоматически переписываются на актуальный домен (kino.watch): старый домен мёртв, и запросы к нему просто не проходят. Отключить это можно флагом `--no-domain-rewrite` — тогда все ссылки используются ровно так, как заданы. Ссылки на зеркала и CDN не трогаются в любом случае.

```bash
# Не подменять старый домен, использовать ссылку как есть
kinopub --no-domain-rewrite https://kino.pub/item/view/38290
```

Куки сессии уходят только на сам сайт (и его поддомены) и никогда — на CDN: CDN режет скорость и подвисает на запросах с `Cookie`.

Флаг `--site` нужен лишь там, где домен не из чего вывести — то есть когда ссылки нет:

```bash
# Локальный feed: ссылки нет, но Referer/куки всё ещё нужны для CDN
kinopub --feed-file ./feed.xml --site kino.watch -o ./downloads
```

Если куки в браузере найдены для одного домена, а качаете вы с другого, утилита предупредит об этом и всё равно попробует их использовать (зеркала часто делят сессию).

### Выбор качества видео

По умолчанию качество подбирается автоматически («оптимальное»: 1080p/h264 с разумным битрейтом, иначе ближайшее). Можно задать явно через `-q` или выбрать из списка через `--video-menu`.

```bash
# Явно
kinopub -q 1080p https://kino.watch/item/view/38290

# Максимальный битрейт из доступных
kinopub -q max https://kino.watch/item/view/38290

# Интерактивный список
kinopub --video-menu https://kino.watch/item/view/38290
```

Меню показывает варианты лучшим сверху и схлопывает дубликаты по паре «разрешение + кодек» — источник часто отдаёт один и тот же 1080p/h264 в нескольких битрейтах, и в списке они неразличимы:

```text
Available video qualities (choose within 1m30s, Enter or TAB = automatic):
  1. 1080p/h265 (2500 kbps)
  2. 1080p/h264 (4200 kbps)
  3. 720p/h264 (1800 kbps)
Selection (e.g. 1; Enter/TAB or 'auto' to keep automatic):
```

В отличие от аудио и субтитров здесь выбирается **один** вариант — он применяется ко всем сериям прогона. Enter, TAB или `auto` оставляют автоподбор.

### Интерактивный режим (`-i`)

Флаг `-i` включает все три меню подряд, в том порядке, в котором они сужают загрузку: качество → аудио → субтитры.

```bash
kinopub -i https://kino.watch/item/view/38290
```

Равносильно `--video-menu --audio-menu --subs-menu`. Любое меню можно пропустить на месте, нажав Enter или TAB.

### Ссылка на конкретную серию

Суффикс `/s1e1` в ссылке работает как фильтр — можно просто скопировать адрес из браузера:

```bash
# Одна серия
kinopub https://kino.watch/item/view/38290/s1e1

# Весь сезон
kinopub https://kino.watch/item/view/38290/s2
```

Регистр и ведущие нули неважны (`S01E01` = `s1e1`). Явные флаги приоритетнее: если указан `--seasons` или `--episodes`, суффикс для соответствующего измерения игнорируется.

### Выбор аудиодорожек

По умолчанию скачиваются **все** аудиодорожки. Часто нужна только одна озвучка (например AniLibria) — её можно выбрать флагом `--audio` или интерактивно через `--audio-menu`.

```bash
# Только дорожки, содержащие "anilibria" в названии или языке
kinopub --audio anilibria https://kino.watch/item/view/38290

# Все дорожки, кроме японского оригинала (префикс '!' или '-' исключает)
kinopub --audio "!jpn" https://kino.watch/item/view/38290

# AniLibria, но никогда японскую
kinopub --audio "anilibria,!jpn" https://kino.watch/item/view/38290

# Интерактивное меню: показать список и выбрать в течение ~90 секунд
# (Enter или TAB — оставить все дорожки и сразу продолжить)
kinopub --audio-menu https://kino.watch/item/view/38290
```

**Умное сопоставление.** Названия дорожек меняются от серии к серии. В одной серии озвучка подписана как `01. Многоголосый. AniLibria (RUS)`, в другой — просто `02. AniLibria`. Совпадение ищется по подстроке (без учёта регистра) и по языку, поэтому шаблон `anilibria` найдёт дорожку в обоих случаях. При интерактивном выборе из первой серии извлекается отличительное ключевое слово студии, и оно применяется ко всем сериям.

**Фоллбек.** Если выбранной озвучки в какой-то серии нет, скачивается другая дорожка на том же языке (например другая RUS-озвучка, а не японский оригинал). Если фильтр исключает вообще все дорожки, исключение игнорируется — в файле всегда останется хотя бы одна аудиодорожка.

### Выбор субтитров

По умолчанию в контейнер вшиваются **все** субтитры. Выбрать нужные можно флагом `--subs` — синтаксис и умное сопоставление те же, что у `--audio`.

```bash
# Только русские субтитры
kinopub --subs rus https://kino.watch/item/view/38290

# Все, кроме английских
kinopub --subs "!eng" https://kino.watch/item/view/38290

# Интерактивное меню
kinopub --subs-menu https://kino.watch/item/view/38290

# Отдельными .srt файлами вместо вшивания в контейнер
kinopub --subs rus --subs-external https://kino.watch/item/view/38290

# Только субтитры — без видео и аудио
kinopub --subs-only --subs rus https://kino.watch/item/view/38290
```

**Отличие от аудио.** Видео обязано содержать звук, поэтому у аудио фоллбек срабатывает всегда. Субтитры же необязательны: если запрошенных нет, берётся одна запасная дорожка на том же языке, а если субтитров нет вовсе — файл просто останется без них.

**Отдельные файлы (`--subs-external`).** Субтитры сохраняются рядом с эпизодом как `S01E01.rus.srt` — по конвенции, которую плееры подхватывают автоматически. Если несколько дорожек на одном языке, вторая и последующие получают числовой суффикс (`S01E01.rus.2.srt`), чтобы не затирать друг друга.

**Только субтитры (`--subs-only`).** Видео и аудио не скачиваются вообще — полезно, когда серия уже есть, а субтитров к ней нет. В этом режиме выбор **строгий**: если в серии нет запрошенного языка, это ошибка, а не молчаливая подмена другим. Серии без нужных субтитров пропускаются с предупреждением, остальные сохраняются, а прогон завершается с ненулевым кодом возврата.

> Выбор субтитров работает только через HLS-конвейер — то есть по ссылке на страницу с авторизацией. При скачивании из podcast feed утилита получает уже готовый файл и лишь сохраняет то, что в нём есть; в этом случае будет выведено предупреждение.

```bash
kinopub logout
```


Или для текущей сессии:

```fish

```

```bash

```

Дополняются подкоманды (`login`, `logout`, `doctor`), все флаги с описаниями, а для флагов с фиксированными значениями (`--quality`, `--container`, `--verbosity`, `--browser-cookies`, `--color`) предлагаются варианты.

## Проверка и восстановление загрузок

`kinopub doctor` сверяет скачанные файлы с state-файлом и помогает восстановить целостность после прерванных или повреждённых загрузок.

```bash
# Проверить текущую директорию
kinopub doctor

# Проверить конкретную директорию
kinopub doctor -o ./downloads

# Восстановить state (удалить битые записи и повреждённые файлы)
kinopub doctor --fix

# Удалить «осиротевшие» .tmp файлы от прерванных загрузок
kinopub doctor --clean-tmp

# Быстрая проверка без сверки длительности (без сети)
kinopub doctor --skip-probe
```

Doctor проверяет:
- Файлы, отмеченные как завершённые, но отсутствующие на диске
- Усечённые файлы (меньше записанного размера)
- Файлы, длительность которых не совпадает с источником (получает свежие медиа-ссылки тем же пайплайном, что и скачивание, и сверяет через ffprobe)
- Записи state без пути к файлу
- Осиротевшие `.tmp` файлы

С флагом `--fix` битые записи state удаляются, а повреждённые файлы стираются — следующий запуск скачивания перекачает затронутые эпизоды.

| Флаг | Назначение |
|------|-----------|
| `-o, --output` | Директория для проверки (по умолчанию: текущая) |
| `--fix` | Восстановить state, удалить битые записи и повреждённые файлы |
| `--clean-tmp` | Удалить осиротевшие `.tmp` файлы |
| `--skip-probe` | Пропустить сверку длительности (без сети, быстрее) |
| `--ffprobe` | Путь к ffprobe (по умолчанию: ffprobe в PATH) |
| `--cookie`, `--user-agent`, `--browser-cookies`, `--proxy` | Авторизация/сеть для получения свежих ссылок |
| `-v` | Подробный вывод |

## Автоматическая загрузка куки из браузера

| Платформа | Safari | Chrome | Firefox |
|-----------|--------|--------|---------|
| macOS | ✅ (Full Disk Access) | ⚠️ (Keychain) | ✅ |
| Linux | — | ✅ | ✅ |
| Termux | — | — | — |

- **macOS Safari**: Требует Full Disk Access для терминала
- **macOS Chrome**: Куки зашифрованы через Keychain, может потребоваться разрешение
- **Linux Chrome/Firefox**: Работает если профиль не зашифрован
- **Termux**: Используй бинарник `kinopub-android-arm64` — он собран специально для Android и не падает с `SIGSYS`. Автозагрузка из браузера недоступна, используйте ручное копирование куки.

## Все флаги

```
kinopub [flags] <url>
kinopub login [flags]       — сохранить авторизацию
kinopub logout              — удалить сохранённую авторизацию
kinopub doctor [flags]      — проверить файлы и восстановить state
kinopub completion <shell>  — сгенерировать скрипт автодополнения (bash, fish)

Основные:
  -o, --output          Директория для сохранения (по умолчанию: текущая)
  -q, --quality         Предпочтительное качество (например: 1080p, 720p, 480p)
  --seasons             Выбор сезонов (например: 1,3-5)
  --episodes            Выбор эпизодов (например: 1-12)
  --audio               Выбор аудиодорожек: список шаблонов через запятую;
                        префикс '!' (или '-') исключает (например: "anilibria",
                        "!jpn", "anilibria,!jpn"). По умолчанию — все дорожки
  --audio-menu          Интерактивный выбор аудиодорожки перед скачиванием
                        (только в терминале; Enter/TAB или ~90с бездействия —
                        все дорожки)
  --subs                Выбор субтитров: синтаксис тот же, что у --audio
                        (например rus, !eng, rus,!eng)
  --subs-menu           Интерактивный выбор субтитров перед скачиванием
                        (только в терминале, как и --audio-menu)
  --subs-external       Сохранять субтитры отдельными .srt рядом с эпизодом
                        вместо вшивания в контейнер
  --subs-only           Скачивать только субтитры, без видео и аудио; выбор
                        строгий, требуется ссылка на страницу
  --video-menu          Интерактивный выбор качества видео перед скачиванием
                        (один вариант на весь прогон, только в терминале)
  -i, --interactive     Выбрать качество, затем аудио, затем субтитры
                        (то же, что --video-menu --audio-menu --subs-menu)
  --container           Формат контейнера: mkv (по умолчанию) или mp4
  --dry-run             Показать список эпизодов без скачивания
  --force               Перекачать уже скачанные эпизоды

Сеть:
  --proxy               URL прокси (http://, https://, socks5://)
  -c, --concurrency     Макс. параллельных загрузок (по умолчанию: 2, макс: 16)
  --no-chunked          Отключить chunked HTTP-загрузку (стриминг через ffmpeg)

Авторизация:
  --cookie              Cookie header (для разового использования)
  --user-agent          User-Agent (должен совпадать с браузером куки)
  --browser-cookies     Загрузить куки из браузера: safari, chrome, firefox, auto
  --site                Домен сайта, напр. kino.watch (по умолчанию берётся из ссылки)
  --no-domain-rewrite   Не подменять старый домен сайта (kino.pub) на актуальный
  --header              Доп. HTTP заголовок 'Name: Value' (можно повторять)

Прочее:
  --ffmpeg              Путь к ffmpeg (по умолчанию: ffmpeg в PATH)
  --ffmpeg-args         Доп. аргументы ffmpeg строкой (advanced, см. ниже)
  --x                   Доп. аргумент ffmpeg (повторяемый, advanced, см. ниже)
  --feed-file           Использовать локальный RSS/XML файл вместо сети
  --log-file            Путь к файлу лога
  -v                    Подробный вывод (debug)
  --verbosity           Уровень логирования: quiet, normal, verbose
  --color               Когда красить вывод: auto (по умолчанию), always, never
  --no-color            То же, что --color=never
  --version             Показать версию
```

## Цветной вывод

Справка, предупреждения, отчёт `doctor`, интерактивные меню, логи и полоса прогресса раскрашиваются, когда вывод читает терминал, который это умеет. При перенаправлении в файл или в pipe (`kinopub … > log`, `kinopub … | grep`) escape-последовательности не пишутся — файл остаётся чистым.

Решение принимается отдельно для `stdout` и `stderr`, так что `kinopub update > file` продолжит красить диагностику на экране.

Управление вручную:

```bash
kinopub --color=never  <url>   # никогда, даже в терминале
kinopub --no-color     <url>   # то же самое
kinopub --color=always <url>   # всегда, даже в pipe — например для pager
kinopub --color=always -h | less -R
```

Учитываются и общепринятые переменные окружения:

| Переменная | Действие |
|---|---|
| `NO_COLOR` | выключает цвет (приоритетнее `*_FORCE`), см. [no-color.org](https://no-color.org) |
| `CLICOLOR_FORCE`, `FORCE_COLOR` | включают цвет даже без терминала (полезно для CI, где логи рендерят ANSI) |
| `CLICOLOR=0` | выключает цвет |
| `TERM=dumb` | цвет не используется |

Флаг сильнее переменных: `--color=always` красит при любом `NO_COLOR`, `--color=never` не красит ни при каком `FORCE_COLOR`.

На Windows при включённом цвете консоль переводится в режим обработки ANSI, так что старый `conhost.exe` печатает цвета, а не escape-последовательности.

## Продвинутое: аргументы ffmpeg

Можно передать дополнительные аргументы напрямую в ffmpeg. Они вставляются перед выходным файлом, что позволяет переопределить `-c copy` (stream copy) на перекодирование или добавить фильтры.

**Два способа:**

```bash
# Способ 1: строка (парсится с учётом кавычек)
kinopub --ffmpeg-args "-c:v libx265 -crf 28 -c:a aac" https://kino.watch/item/view/38290

# Способ 2: повторяемый --x (точный контроль каждого аргумента)
kinopub --x "-c:v" --x libx265 --x "-crf" --x 28 https://kino.watch/item/view/38290

# Можно комбинировать
kinopub --ffmpeg-args "-c:v libx265" --x "-crf" --x 28 https://kino.watch/item/view/38290
```

**Примеры использования:**

```bash
# Перекодировать видео в H.265 (HEVC) для экономии места
kinopub --ffmpeg-args "-c:v libx265 -crf 28 -c:a copy" <url>

# Перекодировать аудио в AAC (для совместимости с MP4)
kinopub --container mp4 --ffmpeg-args "-c:v copy -c:a aac -b:a 192k" <url>

# Уменьшить разрешение до 720p
kinopub --ffmpeg-args "-c:v libx264 -vf scale=-1:720 -crf 23 -c:a copy" <url>

# Добавить хардсаб (вшить субтитры в видео)
kinopub --ffmpeg-args "-c:v libx264 -vf subtitles=input.srt -c:a copy" <url>
```

> **Важно:** при указании `-c:v` или `-c:a` вы переопределяете дефолтный `-c copy`. ffmpeg применяет последний указанный кодек, поэтому ваши аргументы имеют приоритет.

## Хранение авторизации

Credentials шифруются AES-256-GCM с ключом, производным от уникального идентификатора машины:

| Платформа | Источник ключа |
|-----------|---------------|
| macOS | IOPlatformUUID (аппаратный UUID Mac) |
| Linux | `/etc/machine-id` (systemd) |
| Termux | `$PREFIX/etc/machine-id` или `/proc/sys/kernel/random/boot_id` |

Это означает:
- Файл `~/.config/kinopub/credentials.enc` бесполезен на другой машине
- Даже при краже файла, без знания machine-id расшифровка невозможна
- На Termux: если используется `boot_id`, credentials сбросятся после перезагрузки. Рекомендуется создать `/data/data/com.termux/files/usr/etc/machine-id` вручную:
  ```bash
  uuidgen > $PREFIX/etc/machine-id
  ```

## Обновление

```bash
# Посмотреть, есть ли новая версия
kinopub update --check

# Обновиться
kinopub update
```

Утилита скачивает бинарник для своей платформы, сверяет его контрольную сумму и заменяет себя. Старый исполняемый файл переписывается на месте, так что путь установки не меняется, а симлинки продолжают работать.

**Обновляться может не всякая сборка.** Заменить себя вправе только бинарник из официального релиза: у него в метаданных записаны тег, репозиторий и коммит, которые проставляет workflow при сборке. Собранный локально `go build`, из ветки вместо тега или из дерева с незакоммиченными правками — такой бинарник сообщит о новой версии и на этом остановится. Обновить его автоматически значило бы стереть ровно то, ради чего он собирался.

**Откуда именно обновляется.** Из того репозитория, из которого собран, — он записан внутри. Форк, публикующий свои релизы, обновляет своих пользователей у себя; чужие релизы до них не доходят, и наоборот. Никакой настройки для этого не нужно.

### Что проверяется при обновлении

| | |
|---|---|
| Транспорт | только HTTPS |
| Хост загрузки | закреплён за GitHub — адрес ассета из ответа API не принимается на веру |
| Целостность | SHA-256 против `checksums.txt` из релиза |
| Запуск | скачанный бинарник проверяется на работоспособность **до** замены |
| Подпись | если сборка её требует (см. ниже) |

Порядок важен: сумма сверяется раньше, чем файлу выдаются права на исполнение.

Полностью это не защищает от компрометации самого репозитория — от неё спасает только ключ, лежащий офлайн. Но от подмены по пути, битой загрузки и путаницы между форками защищает.

### Подпись релизов (необязательно)

По умолчанию релизы не подписываются, и обновление работает у всех сразу. Если хочется строже:

```bash
go run ./cmd/releasesign keygen
```

Приватную половину положить в секрет репозитория `KINOPUB_SIGNING_KEY`. Публичная выводится из неё автоматически и вшивается в каждый бинарник при сборке — второй секрет заводить не нужно, и рассинхронизироваться им негде.

После этого бинарники из таких релизов принимают **только** релизы, подписанные этим ключом. Убрать подпись, чтобы ослабить проверку, не выйдет: отсутствие подписи для такой сборки — ошибка, а не повод продолжить.

Честная оценка: ключ в секретах того же репозитория не переживёт его компрометации — тот же доступ прочитает секрет или допишет в workflow шаг, подписывающий что угодно. Он закрывает подмену файлов релиза при живом репозитории. Настоящая стойкость — только у ключа, который никогда не попадает в CI.
