# kinopub

CLI-утилита для скачивания видео с kino.watch (бывший kino.pub) в полном качестве — все аудиодорожки (с названиями студий озвучки), все субтитры, мультисезонные сериалы.

Домен нигде не захардкожен: сайт берётся из переданной ссылки, поэтому любое зеркало или новый домен работают без правок кода. См. [Домены и зеркала](#домены-и-зеркала).

## Возможности

- Скачивание по ссылке на страницу (`/item/view/...`) или по прямой ссылке на podcast feed
- Две независимые авторизации: куки залогиненного браузера **или** сессия JSON-API (`--app`)
- Сессию API можно получить двумя путями: взять из установленного приложения (не занимает новый слот) или авторизовать утилиту честно по **QR/коду** (`login --qr`) — работает на ПК без рута и **сама обновляет токен**
- Перенос сессии между машинами: `sessions export` / `sessions import` с версионированным форматом
- Любой домен: kino.watch, kino.pub, произвольные зеркала — ссылка задаёт сайт
- Все аудиодорожки с метаданными (студия озвучки)
- Выбор и фильтрация аудиодорожек (`--audio anilibria`, `--audio '!jpn'`, `--audio-menu`)
- Выбор и фильтрация субтитров (`--subs rus`, `--subs '!eng'`, `--subs-menu`), отдельные `.srt` (`--subs-external`) и режим `--subs-only`
- Выбор сезонов и эпизодов (`--seasons 1,3-5 --episodes 1-12`); суффикс `/s1e1` в ссылке тоже работает как фильтр
- Выбор качества: автоматически, флагом (`-q 1080p`) или интерактивным меню (`--video-menu`)
- Список форматов без скачивания (`-F`) и выбор по нему одним флагом, как в yt-dlp: `-f "1080p-h264+a1+s1"` или `-f "rus"` для всех русских дорожек
- Интерактивный режим `-i`: качество → аудио → субтитры, затем скачивание
- Прогресс-бар в терминале
- Возобновление прерванных загрузок (state-файл)
- Умные повторы при сбоях CDN: проблемный эпизод откладывается и до-качивается позже, чередуясь с остальными (а не пропускается)
- Вежливость к CDN: при `429 Too Many Requests` соблюдается заголовок `Retry-After`, а параллельность автоматически снижается и восстанавливается (адаптивно)
- Ограничение скорости (`--limit-rate 2M`)
- Проверка и восстановление загрузок (`kinopub doctor`)
- Поддержка прокси (HTTP, HTTPS, SOCKS5)
- Контейнеры MKV (по умолчанию) и MP4
- Зашифрованное хранение авторизации (`kinopub login`), обзор и удаление сессий (`kinopub sessions`, `kinopub logout --app`/`--cookie`)
- Уведомления о прогрессе: в Termux (Termux:API) и нативные на рабочем столе (macOS `osascript`, Linux `notify-send`); отключаются насовсем одной командой
- Настройки, которые запоминаются (`kinopub config`) — чтобы не повторять флаг в каждом запуске
- Самообновление (`kinopub update`) с проверкой контрольных сумм; только для официальных сборок

## Установка

### Из релизов (рекомендуется)

Скачайте бинарник для вашей платформы со [страницы релизов](https://github.com/niazlv/kinopub-downloader/releases/latest):

| Платформа | Архитектура | Файл |
|-----------|-------------|------|
| macOS | Apple Silicon (M1/M2/M3) | `kinopub-darwin-arm64` |
| macOS | Intel | `kinopub-darwin-amd64` |
| Linux | x86_64 | `kinopub-linux-amd64` |
| Linux | ARM64 (Raspberry Pi и др.) | `kinopub-linux-arm64` |
| Android / Termux | ARM64 | `kinopub-android-arm64` |

```bash
# Пример для macOS Apple Silicon:
chmod +x kinopub-darwin-arm64
mv kinopub-darwin-arm64 /usr/local/bin/kinopub

# Пример для Linux:
chmod +x kinopub-linux-amd64
sudo mv kinopub-linux-amd64 /usr/local/bin/kinopub
```

### Из исходников

```bash
go install github.com/niazlv/kinopub-downloader/cmd/kinopub@latest
```

Или:

```bash
git clone https://github.com/niazlv/kinopub-downloader.git
cd kinopub_downloader
go build -o kinopub ./cmd/kinopub
```

## Быстрый старт

### 1. Авторизация

Есть **два независимых пути** авторизации — можно хранить оба и переключаться между ними:

- **Куки сайта** — сайт защищён Cloudflare, поэтому для скачивания через веб нужны куки залогиненного браузера (способы 1 и 2 ниже).
- **Сессия JSON-API** (`--app`) — вместо веба используется API kino.pub. Её можно получить двумя разными способами:
  - **из установленного приложения** (способ 3) — переиспользует уже занятый слот устройства, но требует рут и Android;
  - **своя, по QR/коду** (способ 4) — утилита авторизуется как самостоятельное устройство: работает **на ПК, без рута и без Android**, и **сама обновляет токен**.

Если сохранены оба пути, обычный запуск `kinopub <url>` без флага сам выбирает **последний по свежести** (по времени сохранения или последнего успешного использования). Явные `--app` / `--cookie` / `--browser-cookies` всегда в приоритете. Что сохранено и что будет использовано — покажет `kinopub sessions`.

Куки хранятся **по сайтам**: у kino.watch своя сессия, у [платформы](#ссылки-платформы) — своя, и вход на один сайт не трогает другой. Запуск отправляет только сессию того сайта, который назван в ссылке. Удалить одну из них — `kinopub logout --cookie --site <домен>`.

**Способ 1: Копирование куки из DevTools (работает везде)**

1. Откройте сайт (kino.watch) в браузере, залогиньтесь
2. Откройте DevTools (F12) → Network
3. Обновите страницу, кликните на первый запрос
4. Скопируйте значение заголовка `Cookie` из Request Headers
5. Скопируйте значение `User-Agent`

```bash
kinopub login \
  --cookie "cf_clearance=...; _identity=...; PHPSESSID=..." \
  --user-agent "Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7) ..."
```

**Способ 2: Автоматическая загрузка из браузера**

Требует Full Disk Access для терминала (System Settings → Privacy & Security → Full Disk Access).

```bash
kinopub login --browser-cookies safari
```

Куки ищутся по очереди для всех известных доменов (kino.watch, затем kino.pub) — не нужно помнить, под каким из них вы залогинены. Для зеркала укажите домен явно:

```bash
kinopub login --browser-cookies safari --site kino.example
```

> Полнее всего способ 2 протестирован на **macOS**. На **Linux и Windows** он тоже работает (Chrome/Firefox через библиотеку kooky), но **не тестировался** — если не сработает, используйте способ 1 (ручное копирование куки) или способ 3.

**Способ 3: Сессия мобильного приложения (`--app`)**

Берёт access-токен из установленного приложения kino.pub и ходит в его JSON-API. Главное преимущество: **не занимает новый слот устройства** — вы переиспользуете уже авторизованную сессию приложения. Удобно, когда слоты на аккаунте заняты.

Токен можно взять двумя путями:

```bash
# а) С рутованного устройства (Termux): прочитать токен прямо из приложения.
#    Запускать нужно ОТ ROOT — иначе доступа к данным приложения нет.
su -c 'kinopub login --app'          # KernelSU/обычный su
sudo kinopub login --app             # где есть sudo

# б) Где угодно: передать токен явно (без рута).
kinopub login --app --app-token <ТОКЕН>
```

После `login --app` сессия сохраняется зашифрованной, и дальше **рут и флаги больше не нужны** — токен читается из хранилища:

```bash
kinopub --app https://kino.pub/item/view/126715
# либо вообще без --app, если это последняя по свежести сессия:
kinopub https://kino.pub/item/view/126715
```

Важные свойства режима `--app`:

- **Утилита никогда не повышает себе права.** Она не вызывает `su`/`sudo` — даже по запросу. Если токен нужно прочитать из приложения, а рута нет, она об этом скажет и подскажет команду для перезапуска под рутом. Читать чужие приватные данные должен пользователь осознанно, а не загрузчик сам по себе.
- **Этот токен утилита не обновляет — никогда.** Он принадлежит приложению; ротация здесь разлогинила бы приложение на телефоне. Когда токен истекает, API отвечает `401`, и утилита пишет: открой приложение (оно само освежит сессию), затем `kinopub login --app` заново. Автообновление есть только у своей сессии — см. способ 4.
- **User-Agent совпадает с приложением.** Строки версии/ExoPlayer/OkHttp вычитываются из установленного APK во время выполнения, чтобы не устаревать; при недоступности APK берутся вкомпилированные значения.

**Способ 4: Своя сессия по QR / коду (`login --qr`)**

Честная авторизация: утилита просит kino.pub авторизовать **саму себя**, а не выдаёт себя за приложение. Поэтому она работает **на обычном ПК** — без рута, без Android и без установленного приложения. Это тот же режим `--app` (тот же JSON-API), просто токен получен своим путём.

```bash
kinopub login --qr
```

В терминале появится QR-код и короткий код: отсканируйте код телефоном или откройте ссылку и введите код. После подтверждения сессия сохраняется, и дальше — как обычно:

```bash
kinopub --app https://kino.pub/item/view/126715
```

Свойства этого способа:

- **Токен обновляется автоматически.** Сессия принадлежит утилите, поэтому ротация никому не вредит: она продлевается сама, заранее (за 5 минут до истечения) и при отказе `401`. Перелогиниваться не нужно.
- **Занимает отдельный слот устройства** — в отличие от способа 3. Это плата за честность: аккаунт видит именно эту утилиту.
- **User-Agent честный** — утилита представляется собой, а не Android-приложением.
- **Нужен OAuth client secret** (один раз). kino.pub не выдаёт публичный OAuth-клиент, поэтому используются client_id/secret приложения. Секрет достаётся из APK — то есть один раз на рутованном телефоне (`login --app` его попутно сохраняет), после чего переносится на ПК через `sessions export`/`import`. Либо передайте его явно: `kinopub login --qr --client-secret <SECRET>`.

> Все Credentials (куки и токены) сохраняются зашифрованными в `~/.config/kinopub/credentials.enc` и привязаны к конкретному устройству — расшифровать на другой машине невозможно. Для переноса есть `sessions export`/`import` (см. ниже).

> На Termux `login --app` под `su` кладёт файл в домашний каталог пользователя (а не в `~/.suroot`), и сохранённая сессия переживает перезагрузку.

### 2. Скачивание

```bash
# По ссылке на страницу (самый простой способ)
kinopub -o ./downloads https://kino.watch/item/view/38290

# По ссылке со страницы платформы (сайта поверх этой утилиты) — как есть, из адресной строки
kinopub --browser-cookies https://kino.example/#/title/201

# По прямой ссылке на podcast feed (не требует авторизации)
kinopub -o ./downloads https://kino.watch/podcast/get/38290/TOKEN

# Только 1 сезон, 1080p
kinopub -o ./downloads --seasons 1 -q 1080p https://kino.watch/item/view/38290

# Через сессию приложения (JSON-API), без куки
kinopub --app https://kino.pub/item/view/126715

# Ограничить скорость и снизить параллельность (щадящий режим для CDN)
kinopub --limit-rate 2M -c 1 https://kino.watch/item/view/38290

# Посмотреть что будет скачано (без загрузки)
kinopub --dry-run https://kino.watch/item/view/38290
```

### Два конвейера: что где работает

Утилита выбирает конвейер сама, по тому, что вы передали:

- **Страница** (`/item/view/…`) с авторизацией — включая режим `--app` — идёт через **HLS**: каждая дорожка качается отдельно, поэтому доступен весь выбор.
- **Podcast feed** (`/podcast/get/…`) и `--feed-file` идут через **RSS**: оттуда приходит уже готовый файл, и выбирать внутри него нечего.
- **Страница платформы** (`…/#/title/…`) идёт через **HLS** по манифестам самой платформы: нужна её сессия, а не площадки, и отката на RSS нет — feed платформа не публикует. См. [Ссылки платформы](#ссылки-платформы).

Если HLS-конвейер не завёлся (нет куки, страница не отдалась), происходит откат на RSS — кроме режима `--app`, где JSON-API является единственным источником и настоящая ошибка важнее, и кроме страниц платформы, у которых feed'а нет вовсе.

| Возможность | Страница / `--app` (HLS) | Feed / `--feed-file` (RSS) |
|---|---|---|
| Качество `-q` | да | да (выбор между записями feed) |
| Меню качества `--video-menu` | да | нет, предупреждение |
| Список форматов `-F` | да | да: записи feed, а с ffprobe и дорожки внутри файла |
| Выбор по нему `-f` | да | только качество; дорожки файла остаются как есть, предупреждение |
| Выбор аудио `--audio`, `--audio-menu` | да | нет, сохраняются все дорожки |
| Выбор субтитров `--subs`, `--subs-menu` | да | нет, сохраняется то, что уже в файле |
| Отдельные `.srt` `--subs-external` | да | нет, предупреждение |
| Только субтитры `--subs-only` | да | нет, запуск завершается ошибкой |
| Сезоны и эпизоды `--seasons`, `--episodes` | да | да |
| Возобновление, `doctor`, ретраи, `--limit-rate` | да | да |
| Постер сериала | да | да |
| Нужна авторизация | да | нет, токен уже в ссылке |

Там, где выбор не поддерживается, утилита пишет предупреждение и продолжает — молча деградировать она не будет. Исключение — `--subs-only`: скачать вместо одних субтитров полные эпизоды означало бы сделать ровно противоположное просьбе, поэтому запуск завершается ошибкой.

### Домены и зеркала

Утилита не привязана к конкретному домену. Сайт определяется хостом переданной ссылки, и от него зависят всё остальное: адрес podcast feed, заголовок `Referer` и то, куда отправляются куки сессии.

```bash
# Новый домен
kinopub https://kino.watch/item/view/38290

# Старая ссылка на kino.pub тоже работает — домен автоматически
# заменяется на актуальный (см. ниже)
kinopub https://kino.pub/item/view/38290

# Любое зеркало — просто передайте его ссылку
kinopub https://kino.example/item/view/38290
```

Ссылки со старым доменом сайта (kino.pub) — переданная в аргументе, а также page/media/poster-ссылки внутри feed — автоматически переписываются на актуальный домен (kino.watch): старый домен мёртв, и запросы к нему просто не проходят. Отключить это можно флагом `--no-domain-rewrite` — тогда все ссылки используются ровно так, как заданы. Ссылки на зеркала и CDN не трогаются в любом случае.

```bash
# Не подменять старый домен, использовать ссылку как есть
kinopub --no-domain-rewrite https://kino.pub/item/view/38290
```

Куки сессии уходят только на сам сайт (и его поддомены) и никогда — на CDN: CDN режет скорость и подвисает на запросах с `Cookie`.

Флаг `--site` нужен лишь там, где домен не из чего вывести — то есть когда ссылки нет:

```bash
# Локальный feed: ссылки нет, но Referer/куки всё ещё нужны для CDN
kinopub --feed-file ./feed.xml --site kino.watch -o ./downloads
```

Если куки в браузере найдены для одного домена, а качаете вы с другого, утилита предупредит об этом и всё равно попробует их использовать (зеркала часто делят сессию).

### Ссылки платформы

Платформа — сайт, построенный поверх контракта манифеста этой утилиты: резолв она делает сама, видео отдаёт через свой шлюз, а утилите нужна только её сессия. Ссылка на тайтл там выглядит как `https://kino.example/#/title/201`, на серию — `https://kino.example/#/title/201/s1e3` (так адрес показывает сама страница во время просмотра; регистр и нули в номерах не важны), на сезон целиком — `…/#/title/201/s2`. Старая форма с числовым id серии, `…/#/title/201/1234`, тоже понимается. Утилита узнаёт ссылку по этой форме; домен значения не имеет.

Такая ссылка вставляется как есть, из адресной строки. Вход — сессия платформы, а не kino.watch: сохранённые куки площадки на неё не отправляются. Проще всего взять сессию из браузера, в котором вы залогинены на платформе:

```bash
# Разово, из браузера
kinopub --browser-cookies https://kino.example/#/title/201

# Или сохранить сессию платформы один раз
kinopub login --browser-cookies --site kino.example
kinopub https://kino.example/#/title/201
```

Сессии хранятся по сайтам: вход на платформу ложится рядом с сессией kino.watch, а не вместо неё, и `kinopub sessions` покажет обе. Сессии `--app` это тоже не касается.

Дальше всё как со страницей площадки: `-F`, `-f`, `-q`, `--audio`, `--subs`, `--seasons`, возобновление. Суффикс серии в ссылке работает как фильтр, ровно как `/s1e1` у площадки: ссылка на серию скачивает только её, на сезон — сезон, а явные `--seasons`/`--episodes` важнее ссылки. Если платформа ответила 401, сессия протухла — залогиньтесь на сайте заново и повторите.

Отдельный случай — ссылка-разрешение `…/d/<токен>` с кнопки «Поделиться» на платформе. Она открывается без входа вообще и передаётся флагом `--from`, без позиционной ссылки:

```bash
kinopub --from "https://kino.example/d/TOKEN"
```

### Выбор качества видео

По умолчанию качество подбирается автоматически («оптимальное»: 1080p/h264 с разумным битрейтом, иначе ближайшее). Можно задать явно через `-q` или выбрать из списка через `--video-menu`.

```bash
# Явно
kinopub -q 1080p https://kino.watch/item/view/38290

# Максимальный битрейт из доступных
kinopub -q max https://kino.watch/item/view/38290

# Интерактивный список
kinopub --video-menu https://kino.watch/item/view/38290
```

Меню показывает варианты лучшим сверху и схлопывает дубликаты по паре «разрешение + кодек» — источник часто отдаёт один и тот же 1080p/h264 в нескольких битрейтах, и в списке они неразличимы:

```text
Available video qualities (choose within 1m30s, Enter or TAB = automatic):
  1. 1080p/h265 (2500 kbps)
  2. 1080p/h264 (4200 kbps)
  3. 720p/h264 (1800 kbps)
Selection (e.g. 1; Enter/TAB or 'auto' to keep automatic):
```

В отличие от аудио и субтитров здесь выбирается **один** вариант — он применяется ко всем сериям прогона. Enter, TAB или `auto` оставляют автоподбор.

### Список форматов и выбор по ним (`-F` и `-f`)

Аналог `yt-dlp -F` и `-f`. `-F` печатает, что предлагает источник, не скачивая: утилита берёт первую серию из выбранных (ссылка с `/s2e10`, `--seasons`/`--episodes` или весь сериал) и показывает качества, аудиодорожки и субтитры:

```text
$ kinopub -F https://kino.watch/item/view/119614/s2e10
S02E10  Многочисленные молитвы  (23:40)
ID          KIND   RESOLUTION  FPS     CODEC      BITRATE    ~SIZE     LANG  NAME                                PATTERN
1080p-h264  video  1920x1080   23.976  h264       3805 kbps  ~644 MiB
720p-h264   video  1280x720    23.976  h264       1933 kbps  ~327 MiB
406p-h264   video  720x406     23.976  h264       1060 kbps  ~179 MiB
a1          audio                      mp4a.40.2  152 kbps   ~26 MiB   rus   01. Многоголосый. StudioBand (RUS)  studioband
a2          audio                      mp4a.40.2  177 kbps   ~30 MiB   jpn   02. Оригинал (JPN)                  jpn
s1          subs                                             ~36 KiB   rus   RUS #01                             rus
s5          subs                                             ~25 KiB   eng   ENG #05                             eng
s6          subs                                             ~25 KiB   chi   CHI #06                             chi
s7          subs                                             ~25 KiB   chi   CHI #07                             chi
Example: kinopub -f "1080p-h264+a1+s1" <url>
         a pattern keeps every match, e.g. -f "rus"; -q, --audio and --subs still work
```

`-f` принимает значения, соединённые через `+`, как в yt-dlp (`-f 137+140`); запятая тоже принимается. Значения бывают трёх видов:

- **качество** в грамматике `-q`: `1080p-h264`, `720p`, `max`;
- **идентификатор дорожки** из таблицы: `a1`, `s2`. Он превращается в шаблон из колонки PATTERN, поэтому выбор переживает серии, где дорожки идут в другом порядке;
- **любой шаблон**: подстрока имени или язык. Шаблон универсален: он берёт **все** совпадения сразу и в аудио, и в субтитрах, так что `-f "rus"` оставит все русские озвучки и все русские субтитры (а `-f "chi"` выше взял бы оба китайских трека). Там, где шаблон не совпал ни с чем, ничего не меняется. `!jpn` исключает; такие значения берите в одинарные кавычки (`-f 'rus+!jpn'`): в bash и zsh `!` раскрывается историей даже внутри двойных, в fish кавычки не нужны.

```bash
# Ровно то, что напечатал -F: качество, первая озвучка, первые субтитры
kinopub -f "1080p-h264+a1+s1" https://kino.watch/item/view/119614

# Все русские дорожки и субтитры, оригинал не нужен
kinopub -f 'rus+!jpn' https://kino.watch/item/view/119614
```

Значение, которое ничему не соответствует (`a9`, опечатка в шаблоне), это ошибка до начала скачивания, а не молчаливый откат: оно скопировано из таблицы. Размеры — оценки: для видео по заявленному битрейту и длительности, для аудио и субтитров по размеру первых сегментов дорожки (пара лёгких запросов на дорожку), поэтому они помечены тильдой. Аудио и субтитры показываются для варианта, который выбрал бы `-q` (по умолчанию «оптимальный»); у остальных вариантов дорожки те же. На feed-ссылке (`/podcast/get/…`, `--feed-file`) `-F` показывает записи feed, а при наличии ffprobe и дорожки внутри файла; `-f` там выбирает только качество, потому что файл скачивается целиком, а о проигнорированных дорожках утилита предупредит.

### Интерактивный режим (`-i`)

Флаг `-i` включает все три меню подряд, в том порядке, в котором они сужают загрузку: качество → аудио → субтитры.

```bash
kinopub -i https://kino.watch/item/view/38290
```

Равносильно `--video-menu --audio-menu --subs-menu`. Любое меню можно пропустить на месте, нажав Enter или TAB.

### Ссылка на конкретную серию

Суффикс `/s1e1` в ссылке работает как фильтр — можно просто скопировать адрес из браузера:

```bash
# Одна серия
kinopub https://kino.watch/item/view/38290/s1e1

# Весь сезон
kinopub https://kino.watch/item/view/38290/s2
```

Регистр и ведущие нули неважны (`S01E01` = `s1e1`). Явные флаги приоритетнее: если указан `--seasons` или `--episodes`, суффикс для соответствующего измерения игнорируется.

### Выбор аудиодорожек

По умолчанию скачиваются **все** аудиодорожки. Часто нужна только одна озвучка (например AniLibria) — её можно выбрать флагом `--audio` или интерактивно через `--audio-menu`.

```bash
# Только дорожки, содержащие "anilibria" в названии или языке
kinopub --audio anilibria https://kino.watch/item/view/38290

# Все дорожки, кроме японского оригинала (префикс '!' или '-' исключает)
kinopub --audio '!jpn' https://kino.watch/item/view/38290

# AniLibria, но никогда японскую
kinopub --audio 'anilibria,!jpn' https://kino.watch/item/view/38290

# Интерактивное меню: показать список и выбрать в течение ~90 секунд
# (Enter или TAB — оставить все дорожки и сразу продолжить)
kinopub --audio-menu https://kino.watch/item/view/38290
```

Исключения с `!` берите в одинарные кавычки: в bash и zsh `!` раскрывается историей даже внутри двойных (`"!jpn"` даст `event not found`), в fish кавычки не нужны. Без кавычек вовсе обходится префикс `-`: `--audio -jpn`, `--audio anilibria,-jpn`.

**Умное сопоставление.** Названия дорожек меняются от серии к серии. В одной серии озвучка подписана как `01. Многоголосый. AniLibria (RUS)`, в другой — просто `02. AniLibria`. Совпадение ищется по подстроке (без учёта регистра) и по языку, поэтому шаблон `anilibria` найдёт дорожку в обоих случаях. При интерактивном выборе из первой серии извлекается отличительное ключевое слово студии, и оно применяется ко всем сериям.

**Фоллбек.** Если выбранной озвучки в какой-то серии нет, скачивается другая дорожка на том же языке (например другая RUS-озвучка, а не японский оригинал). Если фильтр исключает вообще все дорожки, исключение игнорируется — в файле всегда останется хотя бы одна аудиодорожка.

### Выбор субтитров

По умолчанию в контейнер вшиваются **все** субтитры. Выбрать нужные можно флагом `--subs` — синтаксис и умное сопоставление те же, что у `--audio`.

```bash
# Только русские субтитры
kinopub --subs rus https://kino.watch/item/view/38290

# Все, кроме английских
kinopub --subs '!eng' https://kino.watch/item/view/38290

# Интерактивное меню
kinopub --subs-menu https://kino.watch/item/view/38290

# Отдельными .srt файлами вместо вшивания в контейнер
kinopub --subs rus --subs-external https://kino.watch/item/view/38290

# Только субтитры — без видео и аудио
kinopub --subs-only --subs rus https://kino.watch/item/view/38290
```

**Отличие от аудио.** Видео обязано содержать звук, поэтому у аудио фоллбек срабатывает всегда. Субтитры же необязательны: если запрошенных нет, берётся одна запасная дорожка на том же языке, а если субтитров нет вовсе — файл просто останется без них.

**Отдельные файлы (`--subs-external`).** Субтитры сохраняются рядом с эпизодом как `S01E01.rus.srt` — по конвенции, которую плееры подхватывают автоматически. Если несколько дорожек на одном языке, вторая и последующие получают числовой суффикс (`S01E01.rus.2.srt`), чтобы не затирать друг друга.

**Только субтитры (`--subs-only`).** Видео и аудио не скачиваются вообще — полезно, когда серия уже есть, а субтитров к ней нет. В этом режиме выбор **строгий**: если в серии нет запрошенного языка, это ошибка, а не молчаливая подмена другим. Серии без нужных субтитров пропускаются с предупреждением, остальные сохраняются, а прогон завершается с ненулевым кодом возврата.

> Выбор субтитров работает только через HLS-конвейер — то есть по ссылке на страницу с авторизацией. При скачивании из podcast feed утилита получает уже готовый файл и лишь сохраняет то, что в нём есть; в этом случае будет выведено предупреждение.

### 3. Управление сессиями

Посмотреть, что сохранено и какая сессия будет использована по умолчанию:

```bash
kinopub sessions            # обзор
kinopub sessions --check    # ещё и проверить токен приложения онлайн (покажет аккаунт)
```

Удаление — целиком или по одному методу (методы независимы, второй остаётся на месте):

```bash
kinopub logout              # удалить всё
kinopub logout --app        # удалить только сессию приложения, куки оставить
kinopub logout --cookie     # удалить единственные куки сайта, сессию приложения оставить
kinopub logout --cookie --site kino.example   # куки одного сайта, остальные оставить
```

**Перенос сессии на другую машину.** Хранилище зашифровано ключом, привязанным к устройству, поэтому просто скопировать файл нельзя — для переноса есть экспорт:

```bash
# на телефоне (где есть рут и приложение)
su -c 'kinopub login --app'                       # заодно сохранит OAuth client secret
kinopub sessions export --out session.json

# на ПК
kinopub sessions import session.json
kinopub sessions --check                          # убедиться, что всё приехало
kinopub login --qr                                # теперь можно завести и свою сессию
```

- Файл **не зашифрован** и даёт полный доступ к аккаунту — передавайте доверенным каналом и удаляйте после импорта (утилита предупреждает об этом и ставит права `0600`).
- Формат версионирован: в файле есть `schema` и версия утилиты. Импорт **откажется** читать файл более новой схемы, чем понимает сборка, вместо того чтобы понять его наполовину. Различие версий утилиты при совместимой схеме — просто заметка.
- **Происхождение токена переезжает вместе с ним:** сессия, взятая из приложения, и на новой машине остаётся необновляемой — иначе её ротация разлогинила бы телефон.
- Куки сайтов по умолчанию **не** экспортируются (они привязаны к браузеру и домену) — нужны, добавьте `--include-cookie`: уедут логины всех сайтов.
- `sessions import -` читает из stdin, `sessions export --out -` пишет в stdout — удобно для скриптов и контейнеров.

## Уведомления о прогрессе

Утилита показывает прогресс не только в терминале, но и системными уведомлениями — если для этого есть чем воспользоваться, иначе просто молча пропускается:

- **Termux (Android)**: через Termux:API (`termux-notification`). Обновляется на месте с процентами. Нужны и CLI-пакет `termux-api`, **и** само приложение Termux:API; если приложения нет, уведомления автоматически отключаются (загрузка при этом не страдает).
- **macOS**: через встроенный `osascript` — баннер в Центре уведомлений при завершении каждого эпизода и всего прогона.
- **Linux**: через `notify-send` (пакет libnotify), если он установлен.

Дополнительно ставить ничего не нужно: `osascript` есть в macOS из коробки, `notify-send` обычно уже стоит в десктопных дистрибутивах. На Windows системные уведомления пока не отправляются.

### Как их выключить

Если уведомления мешают — их можно выключить один раз и навсегда, не передавая флаг при каждом запуске:

```bash
# Больше не показывать никогда
kinopub config set notifications off

# Вернуть обратно
kinopub config set notifications on
```

Разово, не трогая настройку:

```bash
# Без уведомлений только в этом запуске
kinopub --no-notify https://kino.watch/item/view/38290

# С уведомлениями, даже если в настройках они выключены
kinopub --notify https://kino.watch/item/view/38290
```

Прогресс-бар в терминале от этого не меняется — выключаются только системные уведомления.

## Настройки

Выбор, который вы делаете один раз, незачем повторять флагом в каждом запуске: `kinopub config` сохраняет его, и дальше он применяется сам.

```bash
# Что сейчас настроено и откуда взято
kinopub config

# Изменить
kinopub config set notifications off

# Прочитать одно значение (удобно в скриптах)
kinopub config get notifications

# Забыть настройку — вернуться к поведению по умолчанию
kinopub config unset notifications

# Где лежит файл
kinopub config path
```

| Настройка | Значения | По умолчанию | Что делает |
|---|---|---|---|
| `notifications` | `on`, `off` | `on` | Системные уведомления о прогрессе (Termux / рабочий стол) |

Настройки лежат в обычном JSON — `~/.config/kinopub/config.json`, рядом с зашифрованными credentials, но сам файл не секретный и его можно править руками:

```json
{
  "notifications": false
}
```

Отсутствующий файл и отсутствующий в нём ключ означают одно и то же — «мнения нет», работает значение по умолчанию. Флаг конкретного запуска всегда важнее сохранённой настройки. Если файл испорчен, скачивание не останавливается: выводится предупреждение и берутся значения по умолчанию (а вот `kinopub config` в этом случае честно ругается, чтобы правка не затёрла остальное содержимое).

## Проверка и восстановление загрузок

`kinopub doctor` сверяет скачанные файлы с state-файлом и помогает восстановить целостность после прерванных или повреждённых загрузок.

```bash
# Проверить текущую директорию
kinopub doctor

# Проверить конкретную директорию
kinopub doctor -o ./downloads

# Восстановить state (удалить битые записи и повреждённые файлы)
kinopub doctor --fix

# Удалить «осиротевшие» .tmp файлы от прерванных загрузок
kinopub doctor --clean-tmp

# Быстрая проверка без сверки длительности (без сети)
kinopub doctor --skip-probe
```

Doctor проверяет:
- Файлы, отмеченные как завершённые, но отсутствующие на диске
- Усечённые файлы (меньше записанного размера)
- Файлы, длительность которых не совпадает с источником (получает свежие медиа-ссылки тем же пайплайном, что и скачивание, и сверяет через ffprobe)
- Записи state без пути к файлу
- Осиротевшие `.tmp` файлы

С флагом `--fix` битые записи state удаляются, а повреждённые файлы стираются — следующий запуск скачивания перекачает затронутые эпизоды.

| Флаг | Назначение |
|------|-----------|
| `-o, --output` | Директория для проверки (по умолчанию: текущая) |
| `--fix` | Восстановить state, удалить битые записи и повреждённые файлы |
| `--clean-tmp` | Удалить осиротевшие `.tmp` файлы |
| `--skip-probe` | Пропустить сверку длительности (без сети, быстрее) |
| `--ffprobe` | Путь к ffprobe (по умолчанию: ffprobe в PATH) |
| `--cookie`, `--user-agent`, `--browser-cookies`, `--proxy` | Авторизация/сеть для получения свежих ссылок |
| `-v` | Подробный вывод |

## Автоматическая загрузка куки из браузера

| Платформа | Safari | Chrome | Firefox | Статус |
|-----------|--------|--------|---------|--------|
| macOS | ✅ (Full Disk Access) | ⚠️ (Keychain) | ✅ | протестировано |
| Linux | — | ✅ | ✅ | не тестировалось |
| Windows | — | ✅ | ✅ | не тестировалось |
| Termux | — | — | — | недоступно |

- **macOS Safari**: Требует Full Disk Access для терминала
- **macOS Chrome**: Куки зашифрованы через Keychain, может потребоваться разрешение
- **Linux/Windows Chrome/Firefox**: Работает через библиотеку kooky, если профиль не зашифрован. **Не тестировалось** — при проблемах используйте ручное копирование куки (способ 1) или сессию приложения (`--app`).
- **Termux**: Используй бинарник `kinopub-android-arm64` — он собран специально для Android и не падает с `SIGSYS`. Автозагрузка из браузера недоступна: используйте ручное копирование куки или сессию приложения (`--app`).

## Все флаги

```
kinopub [flags] <url>
kinopub login [flags]       — сохранить авторизацию (куки или --app)
kinopub logout [flags]      — удалить сохранённую авторизацию (всю или --app/--cookie)
kinopub sessions [--check]  — показать сохранённые сессии и какую выберет запуск
kinopub sessions export|import — перенести сессию на другую машину

kinopub update [flags]      — установить последний релиз
kinopub completion <shell>  — сгенерировать скрипт автодополнения (bash, fish)

Основные:
  -o, --output          Директория для сохранения (по умолчанию: текущая)
  -q, --quality         Предпочтительное качество (например: 1080p, 720p, 480p)
  --seasons             Выбор сезонов (например: 1,3-5)
  --episodes            Выбор эпизодов (например: 1-12)
  --audio               Выбор аудиодорожек: список шаблонов через запятую;
                        префикс '!' (или '-') исключает (например: "anilibria",
```

## Цветной вывод

Справка, предупреждения, отчёт `doctor`, интерактивные меню, логи и полоса прогресса раскрашиваются, когда вывод читает терминал, который это умеет. При перенаправлении в файл или в pipe (`kinopub … > log`, `kinopub … | grep`) escape-последовательности не пишутся — файл остаётся чистым.

Решение принимается отдельно для `stdout` и `stderr`, так что `kinopub update > file` продолжит красить диагностику на экране.

Управление вручную:

```bash
kinopub --color=never  <url>   # никогда, даже в терминале
kinopub --no-color     <url>   # то же самое
kinopub --color=always <url>   # всегда, даже в pipe — например для pager
kinopub --color=always -h | less -R
```

Учитываются и общепринятые переменные окружения:

| Переменная | Действие |
|---|---|
| `NO_COLOR` | выключает цвет (приоритетнее `*_FORCE`), см. [no-color.org](https://no-color.org) |
| `CLICOLOR_FORCE`, `FORCE_COLOR` | включают цвет даже без терминала (полезно для CI, где логи рендерят ANSI) |
| `CLICOLOR=0` | выключает цвет |
| `TERM=dumb` | цвет не используется |

Флаг сильнее переменных: `--color=always` красит при любом `NO_COLOR`, `--color=never` не красит ни при каком `FORCE_COLOR`.

На Windows при включённом цвете консоль переводится в режим обработки ANSI, так что старый `conhost.exe` печатает цвета, а не escape-последовательности.

## Продвинутое: аргументы ffmpeg

Можно передать дополнительные аргументы напрямую в ffmpeg. Они вставляются перед выходным файлом, что позволяет переопределить `-c copy` (stream copy) на перекодирование или добавить фильтры.

**Два способа:**

```bash
# Способ 1: строка (парсится с учётом кавычек)
kinopub --ffmpeg-args "-c:v libx265 -crf 28 -c:a aac" https://kino.watch/item/view/38290

# Способ 2: повторяемый --x (точный контроль каждого аргумента)
kinopub --x "-c:v" --x libx265 --x "-crf" --x 28 https://kino.watch/item/view/38290

# Можно комбинировать
kinopub --ffmpeg-args "-c:v libx265" --x "-crf" --x 28 https://kino.watch/item/view/38290
```

**Примеры использования:**

```bash
# Перекодировать видео в H.265 (HEVC) для экономии места
kinopub --ffmpeg-args "-c:v libx265 -crf 28 -c:a copy" <url>

# Перекодировать аудио в AAC (для совместимости с MP4)
kinopub --container mp4 --ffmpeg-args "-c:v copy -c:a aac -b:a 192k" <url>

# Уменьшить разрешение до 720p
kinopub --ffmpeg-args "-c:v libx264 -vf scale=-1:720 -crf 23 -c:a copy" <url>

# Добавить хардсаб (вшить субтитры в видео)
kinopub --ffmpeg-args "-c:v libx264 -vf subtitles=input.srt -c:a copy" <url>
```

> **Важно:** при указании `-c:v` или `-c:a` вы переопределяете дефолтный `-c copy`. ffmpeg применяет последний указанный кодек, поэтому ваши аргументы имеют приоритет.

## Хранение авторизации

Credentials шифруются AES-256-GCM с ключом, производным от уникального идентификатора машины:

| Платформа | Источник ключа |
|-----------|---------------|
| macOS | IOPlatformUUID (аппаратный UUID Mac) |
| Linux | `/etc/machine-id` (systemd) |
| Termux | `$PREFIX/etc/machine-id` или `/proc/sys/kernel/random/boot_id` |

Это означает:
- Файл `~/.config/kinopub/credentials.enc` бесполезен на другой машине
- Даже при краже файла, без знания machine-id расшифровка невозможна
- На Termux: если используется `boot_id`, credentials сбросятся после перезагрузки. Рекомендуется создать `/data/data/com.termux/files/usr/etc/machine-id` вручную:
  ```bash
  uuidgen > $PREFIX/etc/machine-id
  ```

## Обновление

```bash
# Посмотреть, есть ли новая версия
kinopub update --check

# Обновиться
kinopub update
```

Утилита скачивает бинарник для своей платформы, сверяет его контрольную сумму и заменяет себя. Старый исполняемый файл переписывается на месте, так что путь установки не меняется, а симлинки продолжают работать.

**Обновляться может не всякая сборка.** Заменить себя вправе только бинарник из официального релиза: у него в метаданных записаны тег, репозиторий и коммит, которые проставляет workflow при сборке. Собранный локально `go build`, из ветки вместо тега или из дерева с незакоммиченными правками — такой бинарник сообщит о новой версии и на этом остановится. Обновить его автоматически значило бы стереть ровно то, ради чего он собирался.

**Откуда именно обновляется.** Из того репозитория, из которого собран, — он записан внутри. Форк, публикующий свои релизы, обновляет своих пользователей у себя; чужие релизы до них не доходят, и наоборот. Никакой настройки для этого не нужно.

### Что проверяется при обновлении

| | |
|---|---|
| Транспорт | только HTTPS |
| Хост загрузки | закреплён за GitHub — адрес ассета из ответа API не принимается на веру |
| Целостность | SHA-256 против `checksums.txt` из релиза |
| Запуск | скачанный бинарник проверяется на работоспособность **до** замены |
| Подпись | если сборка её требует (см. ниже) |

Порядок важен: сумма сверяется раньше, чем файлу выдаются права на исполнение.

Полностью это не защищает от компрометации самого репозитория — от неё спасает только ключ, лежащий офлайн. Но от подмены по пути, битой загрузки и путаницы между форками защищает.

### Подпись релизов (необязательно)

По умолчанию релизы не подписываются, и обновление работает у всех сразу. Если хочется строже:

```bash
go run ./cmd/releasesign keygen
```

Приватную половину положить в секрет репозитория `KINOPUB_SIGNING_KEY`. Публичная выводится из неё автоматически и вшивается в каждый бинарник при сборке — второй секрет заводить не нужно, и рассинхронизироваться им негде.

После этого бинарники из таких релизов принимают **только** релизы, подписанные этим ключом. Убрать подпись, чтобы ослабить проверку, не выйдет: отсутствие подписи для такой сборки — ошибка, а не повод продолжить.

Честная оценка: ключ в секретах того же репозитория не переживёт его компрометации — тот же доступ прочитает секрет или допишет в workflow шаг, подписывающий что угодно. Он закрывает подмену файлов релиза при живом репозитории. Настоящая стойкость — только у ключа, который никогда не попадает в CI.

```bash
pip install yt-dlp-kinopub
yt-dlp --cookies-from-browser safari "https://kino.watch/item/view/38290/s1e1"
```
